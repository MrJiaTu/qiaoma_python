# 题目顺序解锁

## 背景

qiaoma 的练习界面原本允许随时跳到任意一题。对零基础学员来说，这等于把 280 道题摊成一个题库：容易挑着做、容易提前看到后面的题面，一题一关的节奏也就没了。

这层限制按下面的规则实现。

## 规则

一门课题内部的第 i 道题，满足下面任一条件就可访问：

- 它是该课题的第一题；
- 它前面的题全部已完成；
- 它自己已经完成（回看、重做不受限制）。

课题之间互不影响：每门课题的第一题始终可访问，学员可以从任意轨道开始。

判定用的是「阻塞题」这个概念——该题之前**第一道未完成**的同课题题目。没有阻塞题就是已解锁。用第一道未完成的题而不是紧邻的前一题，是为了在进度数据出现空洞时（比如手工改过 `state.json`），提示仍然指向真正该做的那道题。

通过一题后，进入课程顺序中的下一题（同一课题内就是本课题的下一题）。如果下一题仍被锁（进度数据有空洞），则回退到队列中第一道可访问题。

## 数据从哪里来

解锁状态不单独存储。`state.json` 仍然只有两个字段：

```json
{"completed": ["variables01"], "current": "variables02"}
```

已解锁与否每次都从 `completed` 现算。这样做的原因：

- 只有一份进度数据，不存在「已完成但没解锁」这类不一致；
- 旧工作区不需要迁移；
- 进度数据有空洞时会自动向前推进，不会把异常状态固化下来。

代价是每次判定要扫一遍同课题的前置题目。单门课题 10 题，忽略不计。

## 三个入口，同一道门

限制放在界面和命令行的边界上，判题本身不感知权限：

| 位置 | 行为 |
| --- | --- |
| 做题界面 `load_exercise()` | 目标任务未解锁时只提示、不切题，当前编辑器内容保持不动 |
| 题目列表（F3 / F4 子列表） | 锁定题显示 `🔒 题号 ???`，标题隐藏；选中时提示挡路的是哪道题，弹窗不关闭 |
| `qiaoma hint / run / reset` | 输出同一条提示，退出码 1；`hint` 不泄露提示文本，`run` 不执行判题，`reset` 不覆盖文件 |

`qiaoma init` 仍然把全部题目和检查文件复制到工作区。锁限制的是工具入口，不是文件系统——学员用编辑器打开 `exercises/` 下的文件仍然能看到题面。这是有意的取舍：这个工具的目标是引导学习顺序，不是防作弊。

## 课题列表的二级视图

F4 原来选中课题就直接跳题，学员看不到这门课里有哪些题。现在改成两层：

1. F4 列出 28 门课题；
2. 选中后先显示该课题的题目列表，列表上方给出课题名称、进度和 `info.toml` 里的 `description`；
3. 在列表里选中题目才真正进入编辑器。列表打开时光标停在该课题第一道未完成的题上，直接回车等于原来的行为。

F3 的全局列表和这个子列表共用同一个行渲染函数，锁定样式只改一处，两个视图同时生效。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `qiaoma/core/state.py` | `blocking_exercise()` / `is_unlocked()` / `lock_message()` |
| `qiaoma/screens/exercise.py` | 切题入口的守卫；通过后按队列取下一题 |
| `qiaoma/screens/exlist.py` | 题目行渲染；F3 与课题子列表共用 |
| `qiaoma/screens/picker.py` | 课题选择器；选中后打开子列表 |
| `qiaoma/cli.py` | `hint` / `run` / `reset` 的守卫 |
| `qiaoma/app.py` | 启动时若上次的题已被锁，回退到队列中的第一道可访问题 |

## 测试

- `tests/test_progress.py`：解锁判定的边界，包括进度空洞和已完成题的可访问性；
- `tests/test_navigation.py`：课题子列表、描述显示、Esc 返回、回车进入、光标起点；
- `tests/test_cli_unlock.py`：三个命令对锁定题的拒绝行为；
- `tests/test_tui.py`：切题守卫、启动回退、列表中的锁定样式。

全量运行：

```bash
python -m pytest -q
```

## 已知限制

- 按固定顺序推进，学员卡在某题时只能看提示、重置，或换一门课题；
- 文件层面不设防，直接看文件可以绕过顺序；
- F3 的全局列表仍是 280 行平铺，没有按课题分组。
